# 後で直すか検討すること

レビューで見つかったが、マージを止めるほどではなかった指摘の書き溜め。**優先度は低く、まだ直すと決めたものではない。** 手が空いたときに見直し、直すと決めたものは GitHub の Issue にして、ここからは消す。直す必要がないと決めたものも、理由を書かずに消してよい。

Issue にしないのは、Issue をまとめて片付けるときに一緒に拾われないようにするため。新しい機能の案は [IDEAS.md](IDEAS.md) に書く。

（書き始めた日：2026-10-16）

## 要素の編集

- **要素の名前に `[` や `]` などを入れても通る。** サーバーの `renameElement` と `upsert_elements` に、名前の文字の確かめがないため。`[a]b` のような名前にすると、ほかの式から `[名前]` で参照できなくなる。MCP からは前から起きうるが、詳細欄で名前を変えられるようになって起こりやすくなった。サーバー側で断る。

## シナリオ

- **ほかのシナリオが 1 つでも実行できないと、`set_scenarios` 全体が失敗して何も保存されない。** 要素を消してシナリオ A が壊れると、関係のないシナリオ B の説明を直すこともできない。保存はして、比較の結果にシナリオごとのエラーを入れる形（`runScenarios` と同じやり方）のほうが扱いやすい。
- **実行できなかったシナリオがあると、ほかのシナリオの色がずれる。** 色を、実行できたシナリオの中での位置で決めているため。モデルの中の並び順で決めれば変わらない。
- **名前のないシナリオの仮の名前（scenario N）が、前のシナリオを消すとずれる。** 配列の位置で作っているため。名前のないシナリオは取り込んだモデルでしか起きない。
- **シナリオの上限（8）が 2 か所に分かれている。** `src/viewer/server.ts` の `MAX_SCENARIOS` と、web の `MAX_SERIES`。中核から 1 つの定数で出せば、ずれる心配がなくなる。「元のモデル」の名前も web 側に写しがある。
- **ビューアで要素を消したときの黄色の帯が、中核（`removeElements`）の知らせをそのまま並べている。** `FLOW "Births" の to は "Population" を指していたので空（モデルの外）にしました。` や `シナリオ "…" から "…" の値を消しました。` のように、MCP 向けの書き方（英語の種類名）で、作業者には読みにくい。画面では「Births の行き先をモデルの外にしました」「シナリオ「…」から … の値を消しました」のように言い換えるか、要点だけにする。

## 実際のデータ（CSV）

- **日本語版 Excel で「CSV（コンマ区切り）」として保存すると Shift_JIS になり、文字化けする。** 日本語の要素名がどの列とも合わない、という警告だけが出る。文字化けの文字（U+FFFD）を見つけたら「UTF-8 で保存してください」と知らせるか、少なくとも VIEWER.md に書く。
- **タブ区切りの CSV で、カンマを含む名前に変えると次から読めなくなる。** 区切りの判定が「1 行目にタブがあり、カンマがなければタブ区切り」のため。タブの数がカンマより多ければタブ区切りとするか、カンマを含む名前は `"…"` で囲む。
- **データの時刻に合わせて足した行では、ツールチップのモデルの値が「—」になる。** 線は補った値でその時刻を通っているので、ちょうど比べたい点で値が読めない。補った値を出す。
- **期間外の時刻のデータがあると、横軸がそこまで広がる。** モデルの開始より前の実績を入れると、線のない区間ができる。望ましい場合もあるので、どちらにするか決めて VIEWER.md に書く。
- **データのある要素が、最初はグラフに出ない。** 自分で選ぶまで点が見えない。人に見せるという目的からは、最初から出したほうが親切かもしれない。
- **`1,5` を桁区切りとして 15 と読む。** 小数点にカンマを使う地域の書き方を取り違える。日本語の環境では起きにくい。

## ループ（find_loops）

- **例の population の B ループは、R より見分けにくい。** Population → Deaths のリンクがフローの線に沿って、細いレンズ形になる。Death Rate と Deaths の位置を少しずらす。
- **細長い大きな輪（100 要素を超える）では、見つける前に手数の上限で止まる。** 長さを広げながら探し直すため。実際の SD モデルではまずない形。
- **強連結成分を探す処理（Tarjan 法）が再帰。** 数千要素がつながった鎖のようなモデルでは、呼び出しが深くなりすぎて止まるおそれがある。

## 画像（ヘッドレスのブラウザ）

- **`DevToolsActivePort` を一度読むと読み直さない。** 書いている途中で読んだ場合などに、まれに「接続できません」で失敗しうる。`/json/list` が失敗したら読み直す。
- **ブラウザを閉じるときの `fetch` と WebSocket に時間の上限がない。** ブラウザが固まると `close()` が終わらない。`AbortSignal.timeout` を付ける。
- **ブラウザが見つからないとき、空の `im-browser-*` フォルダが残る。** 一時フォルダを作ってからブラウザを探しているため。順を入れ替える。前からある。
