## 1. Insight Maker の Web 版（ログインが必要なので人の作業）

Web 版の Import/Export は、エディタ右上の共有アイコン（3 つの点を線でつないだ形）の中にある。上向きの矢印が読み込み、下向きの矢印が書き出し。

- [ ] **施策（scenarios）付きのモデルを読み込めるか。** 施策を 2 つ足した `examples/population.json` を、新しい Insight で「Import ModelJSON」から読み込み、エラーにならないか（Web 版が ModelJSON の `scenarios` を読むか、無視するか、断るかは、まだ確かめていない）
- [ ] **書き出しにグラフが付いているか。** 作り直した `models/exports/population.json` を、新しい Insight で「Import ModelJSON」から読み込む
  - SIMULATE を押すと、ADD DISPLAY をしなくても「ストックの推移」のグラフが出るか（ModelJSON の `visualizations` を Web 版が読むかは、まだ確かめていない）
  - 変数（Birth Rate、Death Rate）がフローの右横にあり、リンクの点線が雲を突き抜けていないか
- [ ] **ビューアで直した配置が Web 版でも同じか。** ビューアで要素をドラッグして並べ直したモデルを、AI に「Web 版に読み込めるように書き出して」と頼んで読み込み、ビューアと同じ並びになるか
- [ ] （任意）Web 版で「ModelJSON File...」で書き出したファイルも取り込めるか。これまで試したのは「Download Insight Maker File...」だけ

- [x] **AI と同時に変えたとき。**（2026-10-15、brooks_law の増員の方針で確かめた。知らせが出て、もう一度押すと 0.5 で上書きされた） 編集フォームを開いたまま、AI に同じ要素を変えてもらってから「保存」を押す。「編集しているあいだに…」と知らせが出て、もう一度押すと上書きされるか
- [ ] **AI に配置を頼む。** Claude Code のセッションを始め直してから、「brooks_law の図の配置を整えて」などと頼む。AI が `view_diagram` で図を見ながら直し、ビューアの図がその場で変わるか。仕上がりが見やすいか
- [ ] **大きな図の見え方。** brooks_law を開いてすぐ、名前が読める大きさで出るか（ウィンドウを狭くしたときも）。右下のミニマップをドラッグして、図の全体を行き来できるか。Claude Code で `view_diagram` を頼んだときの画像には、これまでどおり図の全体が入っているか
- [ ] **グラフの要素の選び方。** brooks_law で、グラフの上の帯が 1 行に収まっているか。「要素を選ぶ」で一覧を開き、名前で絞り込んで要素を足せるか。帯の × で外せるか。Esc や一覧の外を押して閉じられるか。8 本出して帯の名前が省略されたときも読み分けられるか
- [ ] **選んだ要素につながるものを目立たせる。** brooks_law で「採用」（弁か名前）を押すと、つながる線と要素だけがふつうに出て、ほかが薄くなるか。何もないところを押すと元に戻るか。薄くした要素の名前が、暗い配色でも見分けられるか
- [x] **ループを目立たせる。**（2026-10-16、brooks_law で確かめた。AI が式からリンクの極性を入れると R 4 本、B 7 本に分かれ、R2「増員で意思疎通の手間が増え、遅れが増える」は赤、B5「増員で作業が進む」は青で目立った。population の「原因」のスライドでも同じ） Claude Code のセッションを始め直してから、「brooks_law のループを探して、増員で遅れるループを図で見せて」などと頼む（`find_loops` と `view_diagram` の `loop`）。極性がなければ、AI がリンクの極性を入れるか。画像で、ループの要素と線だけが R なら赤、B なら青で目立ち、左上にループの名前と R / B が出るか。発表モードの「原因」のスライド（examples の population など）でも、同じようにループが目立つか
- [x] **実際のデータを重ねる。**（2026-10-16、population で確かめた。30 年の値を 1870 から 2500 に書き換えると、点がその場で上に動いた） Claude Code のセッションを始め直してから、「examples/population.data.csv を population の実際のデータとして取り込んで」などと頼む（`import_data`）。グラフの Population の線に白抜きの丸が重なるか。`models/population.data.csv` を Excel などで書き換えて保存すると、画面の点がその場で変わるか
- [ ] **実際のデータの列名の打ち間違い。** `models/population.data.csv` の列名をわざと打ち間違えると、左の「問題」に「もしかして」が出るか
- [x] **施策の比較。**（2026-10-16、population の施策 2 つで確かめた） 作業画面のグラフと発表モードの「比較」のスライドで、「何もしない場合」の灰色の点線と各施策の線が重なって出るか
- [ ] **会議資料と発表モード。** Claude Code のセッションを始め直してから、examples の population（`.json`、`.data.csv`）を作業フォルダに置き、「population の会議資料を作って」と頼む（`set_slides`、`view_slides`）。問題 → 原因 → 解決案 → 比較 → 結論の筋書きができるか。ビューアの「▶ 発表」で開き、← → で進めるか、F で全画面になるか。式や編集の欄が出ないか。開いたまま AI に筋書きや出生率を直してもらうと、その場で変わるか。言いたいことが、SD を知らない人にも伝わる言葉か
- [ ] **会議資料の PDF。** 「population の会議資料を PDF にして」と頼む（`export_slides`）。書き出した `models/exports/population.pdf` を、ほかの PC か、Edge と Chrome 以外のアプリ（Acrobat Reader、スマートフォンなど）で開く。1 スライド 1 ページの 16:9 で、文字化けせず、発表モードと同じに読めるか（2026-10-16 に AI が別の PDF エンジン（MuPDF）で開き、7 ページとも崩れないこと、フォントが埋め込まれていることまでは確かめた）
- [ ] **使い心地。** ドラッグのしやすさ、文字の大きさ、ウィンドウを狭くしたときの見え方、暗い配色（OS の設定）で読みやすいか。気になったところを AI に伝える

## 3. 人が決めること

- [ ] **ライセンス。** エンジン `simulation` が AGPL のため、AGPL-3.0 にする見込みで、まだ LICENSE を置いていない（[ROADMAP.md](ROADMAP.md) の「未決事項」）
- [ ] **E3（要素の追加、削除、名前の変更、線でつなぐ）の進め方。** 画面での操作のしかた（ツールバーから足す、ドラッグで線を引く など）を決めてから作る。必要がなければ、AI に頼む運用のままでもよい
- [ ] **見送った細かい点で困らないか。** レビューで挙がったが、普段の使い方ではほぼ起きないので直していないもの
  - 保存中に別のモデルを開くと、前のモデルのエラーの知らせが、いまのモデルの画面に出ることがある
  - アドレス欄に `#foo.json` と手で打って開くと、そのモデルの変更の知らせを拾わない（一覧のリンクから開けば問題ない）
  - 元に戻すの記録は、同じサーバーにつないだブラウザのタブ同士で共有される
