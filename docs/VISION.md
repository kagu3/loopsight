# 構想と前提

このプロジェクトが目指すものと、そこに至るまでに調べてわかった前提をまとめる（調査日：2026-10-15）。

## 目指すもの

（方針を決めた日：2026-10-16）

### ミッション

システムダイナミクス（SD）を使える人がシミュレーションするだけでなく、SD を知っている人が SD を知らない人に、シミュレーションを通じて SD が問題解決に役立つ道具だと分かってもらい、SD を組織に根付かせられるようにする。

### ミッションを達成するために

ビューアは実際の問題解決に使えるものにする。SD を知らない人でも、ビューアを見れば問題解決につながる情報が一目で分かるようにする。

### 今の課題と解決の方針

今でもシミュレーションはできていて、ビューアも動いている。ただ、一目で言いたいことが分かる資料にはなっていない。資料としての分かりやすさを広げていく。

### 最初の目標

SD を知っている人が、ビューアを会議資料として使い、SD を知らない人に問題を定義し、解決案を示せるようにする。会議では SD を知っている人がその場で説明する。説明なしで分かる資料にするのは、その次の段階にする。

- 今の作業画面は、モデルを作る人のために残す。施策の比較と実際のデータの重ね描きを足す
- 見る人向けに発表モードを足す。資料の筋書きは AI と一緒に作る
- 作るものは [#15](https://github.com/suda0033/sd-modeler/issues/15)〜[#19](https://github.com/suda0033/sd-modeler/issues/19)。その先の案は [IDEAS.md](IDEAS.md)（まだ決まっていない）

### 役割の分け方

AI に画面をクリックさせるのではなく、次のように役割を分ける。

- **AI はモデル（データ）を MCP 経由で直接操作する**
- **画面は人が見て、確かめて、手直しするためのもの**

## 3 段階の構想

| 段階 | 内容 | 状態 |
|---|---|---|
| 1. 中核部分＋MCP | モデルを保持して ModelJSON で読み書きし、`simulation` で実行する中核部分と、それを操作する MCP ツール。Insight Maker とファイルでやりとりする場合にもそのまま使える | 実装済み。Web 版への読み込みも確認済み（[ROADMAP.md](ROADMAP.md)） |
| 2. 見るための Web 画面 | 中核部分と同じモデルを表示し、AI の変更をその場で図とグラフに反映する。図の自動配置もここで入れる | 実装済み（`npm run viewer`） |
| 3. 編集できる Web 画面 | 必要になったら、人が手で直せるようにする | 一部実装済み（式などの編集、配置の保存、元に戻す）。要素の追加・削除はこれから |

段階 1 だけで終われば「Insight Maker 用の MCP」になり、2 と 3 まで進めば「AI 前提の自作モデリングツール」になる。どちらに進んでも、段階 1 の成果は無駄にならない。

## 調査でわかった前提

### Insight Maker 本体について

- **公開されている Web API はない。** 公式に用意されている、プログラムから使う手段は次の 3 つだけ。
  - In-Page Action API：開いているモデルの中（ボタンなど）で動く JavaScript。外部からは呼べない
  - npm パッケージ [`simulation`](https://github.com/scottfr/simulation)
  - R パッケージ sdbuildR
- **利用規約（[/termsofuse](https://insightmaker.com/termsofuse)）が自動アクセスとスクレイピングを禁止している。** サイトの内部エンドポイント（`/api/save_model` や `X-IM-Import` ヘッダー付きの取得など）は存在するが、使わない。**このプロジェクトから insightmaker.com には一切アクセスしない。**
- **現行の Web アプリはオープンソースではない。** 公開されているのはエンジンだけ。旧版（2016〜2018 年ごろ、ExtJS と mxGraph を使用）のソースは scottfr/insightmaker のフォークに残っている。ただし独自ライセンス（AGPL に加えて、画面に InsightMaker.com のクレジットを大きく表示する義務がある）で、ExtJS と mxGraph は別ライセンスが必要になる。そのため使わない。

### エンジン `simulation` について（v9.0.0 で確認）

- Insight Maker 公式のシミュレーションエンジン。Node でもブラウザでも動く。ライセンスは **AGPL**。
- `loadInsightMaker`（XML の読み込み）、`loadModelJSON`、`toModelJSON` がある。**Insight Maker 形式の XML を書き出す機能はない。**
- `loadInsightMaker` は、ルートタグが `InsightMakerModel` でないと受け付けない。`mxGraphModel` のままの XML は、名前を置き換えてから渡す（Web 版も書き出し時に同じ置き換えをしている）。
- 往復テスト（XML → ModelJSON → 再読み込み → 実行）では、システムダイナミクスのモデル（55 要素、585 要素）でストックの計算結果が完全に一致した。
- **エージェントベースのモデル（Population）は ModelJSON に対応していない。** そのため往復できない。
- コードで作ったモデルは、要素の座標がすべて `[0,0]` になる。図として見せるには配置が必要になる。

### ファイル形式について

- [ModelJSON](https://github.com/scottfr/modeljson)（CC0）は、「LLM が生成しやすいこと」を設計目標の一つにした JSON 形式。ストック、フロー、変数、リンク、コンバーター、状態、遷移に対応している。
- **Insight Maker の Web 版は ModelJSON を読み書きできる**（Import/Export メニュー）。そのため、Web 版との受け渡しは ModelJSON ファイルを人が手でインポート・エクスポートする形にする。

## 制約と方針

- **共通のデータ形式は ModelJSON にする。** 中核部分、MCP、将来の Web 画面のすべてで使う。
- **insightmaker.com には自動でアクセスしない**（利用規約）。
- **エンジンが AGPL なので、このプロジェクトも AGPL になる見込み。** LICENSE はまだ決めていない。
- **対象はシステムダイナミクスのモデル。** エージェントベースのモデルは当面扱わない。
