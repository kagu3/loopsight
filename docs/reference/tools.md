# ツールのリファレンス

loopsight の MCP サーバーが AI に渡しているツールの一覧。AI はこの説明を読んで、頼まれたことに合うツールを選んで呼ぶ。人が読むと、AI に何を頼めるか、どこまで細かく指定できるかがわかる。

このファイルは、ツールの定義（`src/mcp/tools.ts`）から `npm run docs` で作っている。手で直さず、ツールを変えたら作り直す（作り直すのを忘れると `npm test` が落ちる）。

## AI に渡している使い方の説明

サーバーにつないだときに、ツールの一覧といっしょに AI に渡している説明（そのまま載せている）。AI がどういう流れでツールを使うかがわかる。

システムダイナミクス（SD）のモデルを作り、実行し、分析するためのツールです（Loopsight）。モデルの形式は Insight Maker の ModelJSON です。

モデルは作業フォルダに ModelJSON ファイル（<モデル名>.json）として保存されます。

関係のあるモデルはサブフォルダにまとめられます（何段でも）。モデル名は作業フォルダからの相対パス（/ 区切り、.json なし。例: ブルックスの法則/brooks_law）で、直下のモデルはファイル名だけです。実際のデータ（<モデル名>.data.csv）はモデルと同じフォルダに置きます。

list_models でモデルとフォルダの一覧を見られます（ビューアの一覧と同じ。作業フォルダの中の実際のフォルダのとおりに並ぶ）。フォルダは create_folder で作り、move_folder で動かし・名前を変え、remove_folder で空のものを消します。モデルは move_model で動かし・名前を変え、remove_model で消します（消すと戻せないので、使う前に人に確かめる）。

進め方:

1. create_model か import_model でモデルを用意する

2. upsert_elements でストック、フロー、変数を追加する。式では他の要素を [名前] で参照する。足りないリンクは自動で追加される

3. 結果に検証エラーが出たら直す。validate_model でも確かめられる

4. run_simulation で実行する。値を振って調べる（感度分析）ときや、いくつかの値をまとめて変えて比べるときは、run_simulation の overrides を変えて何回か実行する。人に見せるシナリオは set_scenarios でモデルに保存する（ビューアのグラフに「元のモデル」と重ねて出る）。保存したシナリオは run_simulation の scenarios: true で「元のモデル」と並べて読める。実際のデータ（実績や観測値）があれば import_data で取り込む。人はビューアのグラフで、モデルの線とデータの点を見比べる

5. 会議などで原因を説明するときは、find_loops でフィードバックループ（R：強める、B：釣り合わせる）を探す。極性が決まっていなければ、upsert_elements で LINK の behavior.polarity を入れる。view_diagram の loop でループを目立たせた図を見られる。時間がたってから効くつながり（発注してから届くまでなど）には、upsert_elements の display.delay: true で遅れの印（‖）を付ける

6. 図の配置を整える。layout_model で座標を付けて保存し、view_diagram で図の画像と、箱の重なり・線が要素や名前の上を通るところ・線の交差・1 か所に集まる線の一覧を見る。気になるところは upsert_elements の display で位置を直し、もう一度 view_diagram で確かめる。説明のときに見てほしい要素（問題になっている在庫など）は、display.emphasis: true で強調すると大きく描かれる。人はビューア（npm run viewer）で同じ図を見ている。要素の補足や図の読み方は、set_annotations で説明する箱の近くに注釈（文字だけのもの）として置ける

   要素が多いときは、set_groups で意味のまとまり（「お店側」「お客側」など）をグループにする。図では属する要素が薄い色の背景で囲まれ、凡例が出る。layout_model は同じグループの要素を近くに集めて並べる

7. 図だけを資料（PDF やスライド）に貼るときは、export_diagram で SVG と PNG に書き出す（既定は exports/<モデル名>/diagram.svg と diagram.png）。人はビューアの図の右上の「書き出す」ボタンで同じものを書き出せる

式の書き方: 足し算などの演算子、[Stock] のような参照、{5 Meters} のような単位つきの数、IfThenElse(cond, a, b)、Years()、Rand() などの関数が使えます。

insightmaker.com には自動でアクセスしません。

## 引数の表の見方

- `loop.elements` のように `.` でつないだ引数は、`loop` の中の `elements` を表す
- `elements[].type` のように `[]` の付いた引数は、配列 `elements` の 1 つ 1 つの中の `type` を表す
- 必須の ○ は、その引数（入れ子なら、それを含むものを渡したときの、その中で）を省けないことを表す
- 既定値は、省いたときに使われる値。説明の「既定は …」から取り出している
- `{ 名前: … }` は、キーを自由に決められるオブジェクト（要素名をキーにするものなど）

## list_models

**モデル一覧**（モデルを変えない）

作業フォルダにあるモデルと、フォルダの一覧を返す（ビューアの左の欄の一覧と同じもの）。サブフォルダの中も（何段でも）たどる。models の name はモデル名（作業フォルダからの相対パス、/ 区切り）、folder はモデルのあるフォルダ（直下なら空の文字列）。folders は、中に（サブフォルダの中も含めて）モデルがあるフォルダと、空のフォルダ（models が 0）。親のすぐあとに子が並ぶ。モデルでないファイルだけがあるフォルダ（exports/ や output/ のような書き出し先）と、先頭が . のフォルダは出さない。

引数はない。

**モデルを作る**

空のモデルを作って保存する。既定のシミュレーション設定は 0 から 100 年、刻み 1、RK1。model に「フォルダ/名前」を渡すと、そのフォルダに作る（フォルダがなければ作る）。

| --- | --- | :-: | --- | --- |
| `model` | 文字列（空にできない） | ○ |  | モデル名（作業フォルダの <モデル名>.json）。サブフォルダのモデルは、作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則/brooks_law） |
| `title` | 文字列 |  |  | モデルの表示名（省略するとモデル名） |
| `description` | 文字列 |  |  |  |
| `simulation` | オブジェクト |  |  |  |
| `simulation.algorithm` | `"RK1"` / `"RK4"` |  |  | 解法。RK1 はオイラー法 |
| `simulation.time_start` | 数 |  |  | 開始時刻 |
| `simulation.time_length` | 数 |  |  | 期間 |
| `simulation.time_step` | 数 |  |  | 刻み幅 |
| `simulation.time_units` | `"SECONDS"` / `"MINUTES"` / `"HOURS"` / `"DAYS"` / `"WEEKS"` / `"MONTHS"` / `"YEARS"` |  |  | 時間の単位 |

## move_model

**モデルを動かす・名前を変える**

モデルを別のフォルダへ動かすか、名前を変える。to は新しいモデル名（「フォルダ/名前」。直下へ戻すときは名前だけ）。付属のファイル（<名前>.data.csv の実際のデータ）もいっしょに動かす。exports/ に書き出したファイルは動かさない。行き先のフォルダがなければ作る。行き先に同じ名前のモデル（か付属のファイル）があれば断る。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `model` | 文字列（空にできない） | ○ |  | モデル名（作業フォルダの <モデル名>.json）。サブフォルダのモデルは、作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則/brooks_law） |
| `to` | 文字列（空にできない） | ○ |  | 新しいモデル名（例: ブルックスの法則/brooks_law_detailed） |

## remove_model

**モデルを消す**（消したものは戻せない）

モデルを消す。<名前>.json と、付属のファイル（<名前>.data.csv の実際のデータ）をいっしょに消す。exports/ に書き出したファイルは消さない（もう人に送ったかもしれないため）。消したファイルは戻せないので、使う前に、どのモデルを消すかを人に伝えて、消してよいか確かめること。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `model` | 文字列（空にできない） | ○ |  | モデル名（作業フォルダの <モデル名>.json）。サブフォルダのモデルは、作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則/brooks_law） |

| --- | --- | :-: | --- | --- |
| `folder` | 文字列（空にできない） | ○ |  | フォルダ名。作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則、事例/在庫） |

## move_folder

**フォルダを動かす・名前を変える**

フォルダを別の場所へ動かすか、名前を変える（中のモデルと付属のファイル、サブフォルダごと）。to は新しいフォルダ名（作業フォルダからの相対パス）。行き先の親のフォルダがなければ作る。行き先に同じ名前のフォルダかファイルがあれば断る。exports/ に書き出したファイルは動かさない。結果の models は、動かしたあとのモデル名。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `folder` | 文字列（空にできない） | ○ |  | フォルダ名。作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則、事例/在庫） |
| `to` | 文字列（空にできない） | ○ |  | 新しいフォルダ名（例: 事例/ブルックスの法則） |

## remove_folder

**空のフォルダを消す**

空のフォルダを消す（空のサブフォルダだけがあるときは、それもいっしょに消す）。中にファイルが 1 つでもあれば消さない。中のモデルは、先に remove_model で消すか、move_model でほかへ動かす。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `folder` | 文字列（空にできない） | ○ |  | フォルダ名。作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則、事例/在庫） |

## layout_model

**図の配置を付ける**

座標のない要素に、重ならないように座標を付けて保存する（ビューアが座標のない要素を仮に並べるのと同じ簡易レイアウト）。reset: true ですべて並べ直す。強調した要素（display.emphasis）は大きくした箱の大きさで並べる。グループ（set_groups）があれば、同じグループの要素が近くに集まるように並べる。注釈（set_annotations）は動かさない。箱は注釈を避けて置くが、雲やフローの線・名前は注釈に重なることがあるので、view_diagram で確かめて直す。結果に図の確認（重なり、線が要素や名前の上を通るところ、線の交差、1 か所に集まる線）を付ける。直すときは view_diagram で図を見ながら upsert_elements の display で位置を変える。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `model` | 文字列（空にできない） | ○ |  | モデル名（作業フォルダの <モデル名>.json）。サブフォルダのモデルは、作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則/brooks_law） |
| `reset` | true / false |  | `false` | いまの座標を捨てて、すべて並べ直す（既定は false） |

## view_diagram

**図を見る**（モデルを変えない）

モデルの図を、ビューアと同じ描き方で PNG の画像にして返す。あわせて、箱の重なり（注釈も含む）、線（フロー、リンク）がつながっていない要素や注釈の上を通るところ、線の交差、リンクがフローの名前の上を通るところ、1 か所に集まる線（ほぼ同じ向きでつながる線、1 つの弁に集まる多くのリンク）、グループ（set_groups）の囲みどうしの重なりとグループに属さない要素が囲みに入っているところ（group_issues）、グループの囲みの範囲（groups）、各要素の位置を返す。位置は upsert_elements の display で直す（ストックや変数は display.coordinates が左上、雲はフローの display.from_coordinates / to_coordinates が中心）。注釈（positions の type が NOTE）は set_annotations の coordinates（左上）で直す。強調した要素（display.emphasis）は大きく描き、重なりなどの確認もその大きさで行う（positions の size も大きくしたもの）。画像には Edge か Chrome が必要（なければ image: false と同じで、一覧だけ返す）。loop を渡すと、そのループの要素と線だけを目立たせ、ほかを薄くし、ループの名前と R / B を図の左上に出す（会議などで原因を説明するときの表示）。遅れの印（display.delay）のあるリンクやフローは、線の途中に ‖ を描く。先の要素の式が元の要素を Delay や Smooth などの時間をまたぐ関数に渡しているのに印のないリンクがあれば、unmarked_delays で知らせる（自動では付けない）。資料に貼る図の画像をファイルにするときは export_diagram を使う。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `model` | 文字列（空にできない） | ○ |  | モデル名（作業フォルダの <モデル名>.json）。サブフォルダのモデルは、作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則/brooks_law） |
| `image` | true / false |  | `true` | 画像を付ける（既定は true）。一覧だけでよければ false |
| `loop` | オブジェクト |  |  | 目立たせるループ |
| `loop.elements` | 文字列の配列（1 個以上） | ○ |  | ループを作る要素名を、つながる順に（find_loops の elements） |
| `loop.name` | 文字列 |  |  | 図に出すループの名前（find_loops の name や「増員で遅れが増える」など。省略すると「強めるループ」などの種類の名前） |
| `width` | 整数（400〜4000） |  | `1600` | 画像の幅（既定 1600） |
| `height` | 整数（300〜4000） |  | `1000` | 画像の高さ（既定 1000） |

## export_diagram

**図を画像に書き出す**

モデルの図だけを、資料（PDF やスライド）に貼る画像にして、作業フォルダの中のフォルダに書き出す。ビューアの図の「書き出す」ボタンと同じ描き方で、画面の図をそのまま写す。書き出し先は既定で exports/<モデル名>/（フォルダにあるモデルは exports/<フォルダ>/<名前>/）で、ファイルは &lt;name>.svg と &lt;name>.png（name の既定は diagram。同じ名前のファイルは置き換える）。SVG は拡大してもぼやけない（文字も &lt;text> のまま）。PNG は scale 倍の解像度（既定 2）。背景は白で、いつも明るい配色。全体図・ズームのボタン・背景の点などの操作用の部品は入れず、図全体が収まるように切り取る。loop を渡すと、view_diagram の loop と同じく、そのループを目立たせ、ループの名前と R / B の札を図の上に付ける。ループごとに name を変えると、別のファイルに残せる。Edge か Chrome が必要。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `model` | 文字列（空にできない） | ○ |  | モデル名（作業フォルダの <モデル名>.json）。サブフォルダのモデルは、作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則/brooks_law） |
| `loop` | オブジェクト |  |  | 目立たせるループ |
| `loop.elements` | 文字列の配列（1 個以上） | ○ |  | ループを作る要素名を、つながる順に（find_loops の elements） |
| `loop.name` | 文字列 |  |  | 図に出すループの名前（省略すると「強めるループ」などの種類の名前） |
| `formats` | 配列（中身: `"svg"` / `"png"`）（1 個以上） |  | 両方 | 書き出す形式（既定は両方） |
| `scale` | 数（1〜4） |  | `2` | PNG の解像度の倍率（既定 2。図が大きいときは、長い辺が 8000 px に収まるよう下げる） |
| `path` | 文字列 |  | exports/<モデル名> | 書き出すフォルダ。作業フォルダからの相対パス（既定は exports/<モデル名>。フォルダにあるモデルは exports/<フォルダ>/<名前>） |
| `name` | 文字列 |  | `diagram` | ファイル名（拡張子なし。既定は diagram） |

## find_loops

**ループを探す**（モデルを変えない）

モデルのフィードバックループ（リンクとフローがつくる因果の循環）を探し、強めるループ（R）か釣り合わせるループ（B）かを返す。R か B かはリンクの極性（behavior.polarity）で決める。フローは行き先のストックを増やし（+）、出元のストックを減らす（-）。- が偶数個なら R、奇数個なら B。極性が決まっていないつながり（polarity のないリンクや、フローの式がリンクなしで自分のストックを見ているところ）があれば kind は unknown にし、undetermined に挙げる。ループは短い順。elements はつながる順で、最後の要素は最初の要素につながる。name（R1、B2 など）は返したループの中での通し番号で、element や max_length を変えると変わる。遅れの印（display.delay）のあるリンクやフローを通るループには、delays にそのつながりを挙げる（遅れのある釣り合わせるループ（B）は、行き過ぎて振れやすい）。view_diagram の loop に elements を渡すと、そのループを目立たせた図を見られる。

| 引数 | 型 | 必須 | 既定値 | 説明 |
| --- | --- | :-: | --- | --- |
| `model` | 文字列（空にできない） | ○ |  | モデル名（作業フォルダの <モデル名>.json）。サブフォルダのモデルは、作業フォルダからの相対パスを / 区切りで（例: ブルックスの法則/brooks_law） |
| `element` | 文字列 |  |  | この要素を通るループだけを返す |
| `max_length` | 整数（1 以上） |  |  | 返すループの要素数の上限 |

| `groups[].rename_to` | 文字列 |  |  | 既存のグループの名前を変える |
| `groups[].color` | `"yellow"` / `"green"` / `"teal"` / `"purple"` / `"pink"` / `"brown"` / `"gray"` |  |  | 背景の色 |

## set_annotations

**図の注釈を置く**

図に注釈（どこにもつながらない、文字だけのもの）を置いて保存する。要素の補足や「この図の読み方」を、説明する箱の近くに書くのに使う。注釈はシミュレーションの要素ではない（式から参照できず、ループや検証、グラフの要素の一覧には出ない）。モデルの annotations に保存し、Insight Maker に読み込ませると消える。id で既存の注釈を探し、あれば重ね、なければ足す（id を省くと「注釈1」のように付ける）。remove で消し、replace: true で今の注釈をすべて置き換える。文字は決まった幅（既定 200）で折り返し、改行（\n）で行を分けられる。coordinates は左上。新しい注釈で省くと、図の下に置く。ビューアの図と view_diagram の図の両方に出る（図の部品は共通）。layout_model は注釈を動かさない（箱は注釈を避けて置くが、雲やフローの線・名前は重なることがあるので、view_diagram で確かめて直す）。結果の diagram_issues に、注釈と要素・線の重なりを返す。view_diagram で図を見て、重なっていれば coordinates を直す。図の左上は、ループを目立たせる表示（view_diagram の loop）でループの名前の札に隠れることがあるので、左上の角は避ける。色の説明（凡例）は注釈で作らない。

| `annotations[].text` | 文字列 |  |  | 文字。改行で行を分けられる。新しく足すときは必須 |
| `annotations[].coordinates` | [数, 数] |  |  | 左上の座標 [x, y]（y は下向き）。新しい注釈で省くと図の下に置く |
| `annotations[].width` | 数 / null |  | `200` | 折り返す幅（60〜800。既定 200）。null で既定に戻す |
| `remove` | 文字列の配列 |  |  | 消す注釈の id |
| `replace` | true / false |  | `false` | 今の注釈をすべて捨ててから annotations を保存する（既定は false） |

## run_simulation
